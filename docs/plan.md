# MVP: статическое выравнивание ударных (C++/JUCE)

## Context

Репозиторий `beat-equalizer` почти пустой: `README.md` и `docs/drum-editor-plan.md`. Исходный план описывает полный продукт (ARA 2, по-ударная нарезка, квантизация, спектральный bleed). Этот документ — только **Этап 1**.

Цель MVP: обычный VST3/AU/Standalone с N входами и N выходами, без ARA и без нарезки. Плагин оценивает **одну задержку и полярность на канал**, применяет дробную задержку и олпасс-ротатор, показывает коррелометр и когерентность суммы. Это уже слышимый инструмент и полигон для ядра анализа на реальных записях.

Почему не ARA в первой версии: обычный плагин проверяет DSP, хостовый routing и UI без лицензии Celemony и без общего документа между инстансами. Кросс-микрофонный доступ решается маршрутизацией всех стемов в один инстанс.

## Рекомендуемый подход

Один инстанс, **N-in / N-out passthrough** (2…24 канала). Пользователь сводит все микрофоны ударных на одну многоканальную дорожку (в Reaper это естественный workflow) либо в standalone загружает набор WAV. Плагин не микширует кит в стерео в основном режиме — он возвращает выровненные стемы на те же каналы.

Анализ без доступа к файлу: кольцевой буфер последних нескольких секунд всех каналов + кнопка Analyze. Оценка TDOA — **GCC-PHAT** в ограниченном окне поиска (~12 мс ≈ 4 м), медиана по кадрам, параболическая интерполяция пика. В `processBlock` только чтение готового снимка состояния и DSP: инверсия, дробная задержка, олпасс.

Standalone — основной стенд для реальных записей: не нужно каждый раз собирать 16 шин в DAW.

### Что сознательно не входит в MVP

- ARA 2, общий документ, несколько инстансов
- Детекция онсетов, классификация ударов, по-ударные задержки
  (когда дойдём: `detector-design-recommendations.md`, не сеть в первом детекторе)
- Нарезка, кроссфейды, квантизация, MIDI-экспорт
- Спектральный bleed, эластик, замена сэмплами
- Полноценный редактор волновых форм на час записи
- Windows-сборка в первом проходе (toolchain есть на macOS; Windows — сразу после того, как macOS VST3 стабилен)
- Ableton Live как целевой хост

## Топология плагина и хосты

**Форматы:** VST3 + AU + Standalone.  
**Шины:** один входной и один выходной bus с одинаковым числом каналов. `isBusesLayoutSupported` принимает 2…24 при `in == out`. Имена шин — `"Input"` / `"Output"`, не по микрофону: именованные моно-шины на 16 каналов плохо живут в AU/Logic и усложняют первый хост.

**Первичный хост MVP:** Reaper (многоканальная дорожка → insert → выровненные каналы обратно в папку). Standalone — разработка и прогон реальных китов. Studio One / Cubase — проверка вторым кругом. Logic — не блокер MVP.

**Компенсация задержки — обязательная часть модели, не «потом».** В realtime канал можно только задержать, не сдвинуть раньше. Поэтому:

1. Считать сырые TDOA `d[i]` относительно опоры (положительное = канал позже опоры).
2. `applied[i] = max(d) - d[i]` — все задержки ≥ 0.
3. `reportedLatency = ceil(max(d)) + groupDelayИнтерполятора`.
4. Хост PDC возвращает кит на место относительно баса/гитары.
5. Dry/A-B идёт через ту же latency, иначе сравнение врёт.

Без PDC «выровнять к комнате» сдвинет весь кит на ~10 мс назад по сессии.

## Архитектура

Три слоя. DSP не знает про JUCE UI и не аллоцирует в аудиопотоке.

```
┌─────────────────────────────────────────┐
│  UI (message thread)                    │
│  таблица каналов, Analyze/Freeze/A-B,   │
│  коррелометр, когерентность, listen     │
└──────────────────┬──────────────────────┘
                   │ APVTS + snapshot
┌──────────────────▼──────────────────────┐
│  PluginProcessor                        │
│  ring buffer, worker, latency, process  │
└──────────┬──────────────────┬───────────┘
           │                  │
           ▼                  ▼
   AlignmentEngine      Realtime DSP
   (worker thread)      FractionalDelay
   GccPhat              AllpassRotator
   median / polarity    polarity invert
```

`src/dsp` — статическая библиотека, линкуется в плагин и в тесты. JUCE в DSP допустим только как FFT (`juce::dsp::FFT`); при нехватке скорости — pffft. FFTW не брать.

### Снимок состояния (lock-free)

```cpp
struct AlignmentSnapshot {
    int numChannels = 0;
    int reference = 0;
    float delaySamples[24]{};    // applied, >= 0
    bool invert[24]{};
    float rotatorCoeff[24]{};    // 0 = bypass
    bool enabled[24]{};
    int latencySamples = 0;
};
```

Публикация: `std::atomic<std::shared_ptr<const AlignmentSnapshot>>` (или два предвыделенных слота + seqlock). Аудиопоток в начале `processBlock` берёт указатель и больше не ждёт. Worker и UI никогда не пишут в delay line.

Ручные override (задержка, полярность, ротатор) живут в APVTS на 24 слота всегда, даже если сейчас открыто 8 каналов. Это стабильные parameter ID для хоста.

## DSP: оценка задержки

### GCC-PHAT

Для пары (reference, channel):

1. Кадр 4096…8192 сэмпла, окно Hann, FFT.
2. `G = X * conj(Y) / (|X * conj(Y)| + eps)` (PHAT).
3. Перед этим — полоса **~100 Hz … 8 kHz** (нули вне полосы). Иначе коррелятор залипает на периоде волны бочки (~20–40 мс) даже при лимите лага.
4. IFFT → GCC. Искать `argmax` **только** в `[-τmax, +τmax]`, где `τmax = distance_m / 343.0`. По умолчанию 4 м ≈ 11.7 мс. Пороги задавать в метрах/миллисекундах, не в сэмплах.
5. Парабола по трём отсчётам: `delta = 0.5*(y[-1]-y[1]) / (y[-1]-2y[0]+y[1])`.
6. Знак пика **невзвешенной** корреляции в этой точке → полярность. PHAT-пик для знака ненадёжен.

Много кадров по кольцевому буферу (hop ~50%), оставить кадры с уверенностью выше порога (высота пика GCC относительно медианы), взять **медиану** задержки и мажоритарную полярность.

Опора: пользователь выбирает канал (по умолчанию 1). Авто-опора можно добавить позже: канал с максимальной энергией атаки.

Если на реальных китах бочка/оверхэд будет систематически промахиваться на период — второй проход: грубая оценка по огибающей онсета, затем GCC-PHAT в узком окне. В первый код это не класть, только заложить точку расширения.

### Дробная задержка (realtime)

Lagrange 5-го порядка на предвыделенной delay line. Максимальная длина: `20 ms * 192 kHz + порядок` на канал. Коэффициенты пересчитывать при смене delay; при движении ручкой — сглаживать delay (1–5 мс time-constant), не прыгать.

Частотный сдвиг фазы (офлайн-рендер из документа) в MVP не нужен: нет ARA-рендера. Качество Lagrange достаточно для превью и для продукта Этапа 1.

### Олпасс-ротатор

Один каскад allpass 1-го порядка (IBP-like) на канал после задержки:

`y[n] = c*x[n] + x[n-1] - c*y[n-1]`

`c` задаётся частотой вращения (параметр) и глубиной 0…1. На Analyze после TDOA — грубый перебор Fc/amount по сетке, максимизирующий когерентность пары (канал + опора); результат применяется только если выигрыш выше порога, иначе канал остаётся на bypass. Перебор идёт в спектре кадра, не прогонами звука, и никогда не в realtime.

### Метрики качества

- **Когерентность суммы** (главный индикатор): по кадру анализа, `mean |FFT(a+b)| / (|FFT(a)|+|FFT(b)|)` в 200 Hz–8 kHz, 0…100%. Отдельно «до» и «после».
- **Коррелометр:** коэффициент корреляции −1…+1 для выбранной пары или для виртуальной стереосуммы; плюс простой goniometer L/R.
- Per-channel corr vs reference — колонка в таблице.

## Анализ в плагине (без ARA)

Кольцевой буфер: 8 с на 24 канала @ 48 kHz float ≈ 37 MB. Писать из `processBlock` lock-free (один writer).

Режимы:

| Режим | Поведение |
|---|---|
| Analyze | Снимок буфера → worker → новый snapshot. Если буфер почти пуст — статус «проиграйте материал». |
| Freeze | Перестать обновлять авто-оценки; ручные правки остаются. |
| Continuous (опционально, после Freeze) | Переоценка раз в ~0.5 с, медианное сглаживание. Для MVP можно отложить, если Analyze стабилен. |

`processBlock` не считает FFT.

## UI MVP

Не DAW-редактор. Экран одного инстанса:

- Транспорт анализа: Analyze, Freeze, A/B (dry с той же latency), Mono Sum (мониторинг: все enabled в моно на выходы 1–2, остальные каналы по-прежнему aligned passthrough — **не** ломать N-out mix).
- Max distance (м), выбор reference.
- Таблица каналов: имя, роль (Close / OH / Room / Hats, только метаданные для Этапа 2), delay ms + samples, polarity auto/+/−, rotator %, enable, corr.
- Индикатор когерентности суммы до/после.
- Коррелометр.
- Компактная отрисовка **снимка анализа** (downsampled min/max по каналам) — для отладки ложных задержек, не полный waveform cache.

Роли в MVP не меняют алгоритм, только подписи и дефолтную опору.

## Standalone-стенд

Отдельный путь в том же editor/processor:

1. Добавить несколько моно/стерео WAV (или один multi-channel).
2. Назначить файл → канал.
3. Play / stop внутренним транспортом, тот же Analyze.
4. Export aligned WAV — почти бесплатно и критично для регрессии на реальных китах.

Это закрывает требование документа «проверить ядро на реальных записях» без 16 шин в DAW.

## Проект и сборка

Репозиторий пустой, toolchain уже есть: CMake 4.1.2, Ninja, Apple Clang 21.

- CMake + `FetchContent` на **JUCE 8.x** (пин конкретного тега, например 8.0.10+).
- C++20.
- `juce_add_plugin`: `NEEDS_MIDI_INPUT/OUTPUT FALSE`, `IS_SYNTH FALSE`, `VST3_CATEGORIES Fx`, `AU_MAIN_TYPE kAudioUnitType_Effect`.
- `PLUGIN_MANUFACTURER_CODE` / `PLUGIN_CODE` — 4 символа, зафиксировать в CMake (рабочие: `Bteq` / `Algn`).
- Модули: `juce_audio_utils`, `juce_dsp`, `juce_gui_extra`.
- Тесты: Catch2 через FetchContent, линк только на `dsp` + `juce_dsp` (без GUI).
- Лизензия JUCE: dual AGPLv3 / commercial. Пока нет коммерческой лицензии — собирать с GPL-режимом JUCE и не шипить закрытый бинарь. Это не блокирует разработку MVP.

## Порядок реализации

Каждый шаг собирается и проверяется до следующего. Не смешивать UI с оценкой TDOA.

### PR 1 — скелет плагина

CMake, JUCE FetchContent, VST3+AU+Standalone, N-in/N-out passthrough, `isBusesLayoutSupported`, пустой editor, APVTS-заготовка на 24 слота. Проверка: Standalone открывается, Reaper видит 8-канальный insert, звук идёт 1:1.

### PR 2 — DSP GCC-PHAT + тесты

Чистая библиотека. Синтетика: импульс и полосовой шум с известной задержкой (целая и дробная, ±0.25 / 0.5 / 1.7 / 11.3 сэмпла), инверсия, два периода бочки как ложный аттрактор за окном. Критерий: ошибка TDOA < 0.1 сэмпла на синтетике внутри окна; вне окна не возвращать соседний период.

### PR 3 — дробная задержка в realtime + PDC

Delay line, invert, `setLatencySamples`, dry с той же latency. Проверка: Impulse на ch1, задержанная копия на ch2, ручная задержка сводит импульсы; Reaper показывает PDC.

### PR 4 — AlignmentEngine + worker + Analyze

Ring buffer, кнопка Analyze, публикация snapshot, Freeze, ручной override. Автозадержка должна совпасть с ручной на синтетическом стереофайле в Standalone.

### PR 5 — олпасс + когерентность + auto-rotate на Analyze

Метрика в UI. На инвертированном нижнем снейре: auto polarity + delay дают рост когерентности; ротатор — второй, меньший вклад.

### PR 6 — UI таблица / коррелометр / A-B / Mono Sum / compact waveform снимка

Редактор, в котором можно работать без отладчика.

### PR 7 — Standalone loader + export aligned WAV + персистентность

Состояние: параметры APVTS + бинарный блоб последних оценок (версия формата). Открытие проекта не должно требовать переанализа, если канальность та же.

### PR 8 — прогон на реальном ките + калибровка порогов

Несколько сессий 8–16 микрофонов. Зафиксировать в `docs/` протокол: ожидаемые задержки OH vs kick ~1–5 мс, snare bottom обычно inverted, комната 5–15 мс. Если GCC-PHAT систематически врёт на kick/OH — тогда envelope pre-align, не раньше.

### PR 9 — монитор-микс стенда: панорама и уровень

Следствие первого прогона на ките. Стенд отдаёт канал клипа в одноимённый выход устройства, поэтому на обычной стерео-карте кит звучит как «нечётные слева, чётные справа», а дорожек дальше второй не слышно вовсе. Нужна сумма всех каналов в 1-2 с панорамой и уровнем на канал.

Правила: монитор-микс работает только когда в стенде загружен материал — внутри хоста N-out passthrough не трогаем (`AGENTS.md`, инвариант 3). Панорама, уровень, Solo/Mute и Mono Sum в `Export aligned` не попадают (инвариант 15). Панорама по умолчанию — центр, а не расстановка по ролям: угадывать образ за инженера нечестно.

## Риски

| Риск | Почему | Что делаем |
|---|---|---|
| GCC залипает на периоде бочки | Самая частая поломка таких алгоритмов | Полоса 100 Hz+, τmax от метров, медиана, тест с ложным периодом |
| Нет «опережения» канала | Realtime | Сдвиг всех к самому позднему + PDC |
| Routing в DAW | 16 каналов в одном insert — не везде | Reaper + Standalone как контракт MVP |
| PHAT и полярность | Знак PHAT-пика лжет | Полярность по обычной корреляции |
| JUCE GPL vs closed | Dual license | Разработка под AGPL, лицензия до продажи |
| Waveform UI раздувается | Документ сам предупреждает | В MVP только снимок анализа |

## Verification

Автотесты (каждый PR с DSP):

- Известная задержка 0, 0.25, 1, 5.5, 11.3 сэмпла @ 48/96 kHz.
- Инверсия нижнего канала.
- Ложный период 20 мс при τmax = 12 мс — не выбрать его.
- `applied delay >= 0`, `latency == max(d) + interpolator`.
- Dry/wet одинаковая latency (корреляция пика A/B по времени = 0).

Ручная приёмка MVP:

1. Standalone: 2 WAV, один сдвинут на 2.3 мс и инвертирован → Analyze находит, A/B и mono-sum слышно.
2. Standalone: 8–16 реальных стемов → таблица задержек физически правдоподобна, когерентность после > до.
3. Reaper: многоканальная дорожка, PDC, bypass не щёлкает по времени.
4. Сохранить/открыть проект — задержки на месте без Analyze.
5. Смена sample rate 44.1 ↔ 48 ↔ 96 — задержки в мс те же.

# Git: trunk на main до первой прод-версии

Status: accepted  
Date: 2026-08-30

## Context

Два разработчика, продукт ещё не издан. Нужен обязательный PR-поток и вопрос:
заводить ли `develop` сейчас или когда появится v1.

## Decision

До первой версии в проде:

- долгоживущая ветка одна — `main`;
- вся работа через PR в `main` (и владелец репо тоже);
- squash-merge;
- ветки `feat/` `fix/` `chore/` `docs/` `test/` короткоживущие;
- `develop` не создавать.

После v1.0.0 — `develop` как интеграция следующей линии, `main` как изданное,
хотфиксы в `main`. Подробности: `docs/git-workflow.md`.

## Alternatives

- **Git Flow сейчас** (`develop` + `main`). Пока нет пользователей, `main`
  пустеет, каждый PR целит не туда, агенты путают целевую ветку. Два человека
  получают церемонию релиза без релиза.
- **Прямой пуш в `main`.** Ломает историю для второго разработчика и для агента:
  нет границы «готово к интеграции», нет места для ревью.
- **Trunk + обязательный PR** — выбран. Интеграция одна, ревью есть,
  `develop` появляется в момент, когда его нечем заменить (нужен хотфикс
  изданного плагина на фоне этапа 2).

## Consequences

Сейчас защищать нужно только `main` (GitHub: require PR). Когда заведём
`develop`, правила AGENTS и этот ADR обновляются в одном изменении — не раньше.

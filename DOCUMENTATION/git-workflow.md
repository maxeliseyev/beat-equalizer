# Git workflow

До первой версии в проде работаем с **одной** долгоживущей веткой `main`.
Ветку `develop` не заводим. Решение и триггер смены: `decisions/git-trunk-until-v1.md`.

---

## Сейчас (до v1)

```
main  ← единственная интеграция, всегда зелёная
  ↑
  PR (squash)
  ↑
feat/gcc-phat   fix/pdc-click   chore/clang-format   docs/agents-md
```

1. Обновить `main`: `git checkout main && git pull`.
2. Ветка от актуального `main`: `feat/…`, `fix/…`, `chore/…`, `docs/…`, `test/…`.
3. Коммиты — Conventional Commits (`feat(dsp): …`).
4. Открыть PR **в `main`**. Пуш напрямую в `main` запрещён обоим, включая автора репо.
5. Зелёная сборка + тесты. Definition of done — в `AGENTS.md`.
6. Ревью: второй разработчик. Если его нет на этом PR — всё равно PR,
   self-merge только с явной пометкой в описании (`self-merge: <причина>`).
7. Merge: **squash**. История `main` = один пункт плана / один фикс на коммит.
8. Удалить ветку после merge.

Не пушить в чужую feature-ветку без договорённости. Не копить локальные
коммиты на `main`.

Незаконченная сессия: push feature-ветки (хотя бы draft PR) и имя ветки в
`STATUS.md`. Local working tree на `main` второй человек не подхватит.

### Имена веток

| Префикс | Когда |
|---|---|
| `feat/` | Шаг плана или новая возможность (`feat/gcc-phat`) |
| `fix/` | Баг на уже слитом поведении |
| `test/` | Только тесты |
| `docs/` | Документация, AGENTS, ADR |
| `chore/` | CMake, формат, зависимости |

Имя короткое, латиница, без номера PR в названии ветки.

### PR

- Один PR = один шаг `DOCUMENTATION/plan.md` или один связный фикс.
- В описании: зачем, как проверить, какие инварианты из `AGENTS.md` задеты.
- Не смешивать DSP-ядро и UI «чтобы сразу было видно».
- Не тащить bump JUCE, реформат всего дерева и фичу в одном PR.

### Теги

Тег `v0.y.z` — только когда артефакт отдают наружу (тестеру, в DAW как
«попробуй это», не каждый merge). Пока продукт внутренний, теги не обязательны.

## После первой версии в проде

Когда появляется то, что нельзя сломать следующими экспериментами
(плагин у пользователей / в продаже / отдан как v1):

1. Пометить `main`: `v1.0.0`.
2. Завести `develop` от этого тега. Новая работа идёт `feat/*` → PR в **`develop`**.
3. `main` = последняя изданная линия. Хотфикс: `hotfix/…` от `main` → PR в `main`
   → тег `v1.0.x` → cherry-pick (или merge) в `develop`.
4. Релиз следующей мажорной: PR или merge `develop` → `main`, тег `v1.1.0` / `v2.0.0`.

До этого шага имитировать Git Flow незачем: `develop` будет вторым `main`
без пользователей на первом.

Эту секцию не включать в код и CMake заранее. Когда дойдёте до v1 — обновить
этот файл и `AGENTS.md` в одном PR.
